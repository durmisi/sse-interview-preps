## Structure of every module

| Part | Content |
|---|---|
| Header | Learning objective, audience, how to use, progress tracker, module boundaries (cross-references) |
| Part I — Complete Curriculum | Every section and subtopic, with an outcome and a senior-level bar per section |
| Part II — Lessons | **Every section and every subtopic fully taught**: fundamentals → internals → C#/.NET → enterprise scenario → trade-offs → senior expectations → interview Q&A → exercises, plus a review (knowledge check + completion criteria) per section |
| Part III — Interview Readiness | Mid vs senior answer patterns, rapid-fire revision sheet, self-assessment rubric |
| Part IV — References | Authoritative docs, RFCs, books and papers |

## How to study

1. Work through one module at a time, starting with Part I to see the whole map.
2. Study Part II lesson by lesson and answer every exercise **before** looking anything up.
3. After each section, do the section review; mark the section in the progress tracker and note your knowledge gaps.
4. Before interviews, revise with Part III (revision sheet + rubric).
5. To get feedback, paste your exercise answers into a conversation with a mentor/AI and ask for a senior-level review with follow-up questions.

## Suggested order

Modules are independent, but this order builds naturally:

```text
01 Fundamentals -> 04 Patterns -> 03 .NET Internals -> 02 DSA
-> 05 Databases -> 06 APIs -> 07 Distributed Systems -> 08 System Design
-> 09 Testing -> 10 Code Reviews -> 11 DevOps -> 12 Leadership
```

Run Module 02 (coding practice) and Module 12 (behavioral story bank) continuously in parallel with the others; both need repetition over weeks, not a single pass.
